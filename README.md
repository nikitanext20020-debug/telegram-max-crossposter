# Автоматический Telegram → MAX

Сервис читает настраиваемые Telegram-каналы через личный Telegram-аккаунт,
держит постоянную очередь в Neon Postgres и публикует уникальные посты в MAX
по расписанию. Он рассчитан на бесплатный Render: процесс может засыпать, а
Upstash QStash будит его для сканирования и каждого времени публикации.

Целевой канал: `https://max.ru/channel_animenaruto`.
Первый источник: `https://t.me/animeworldmem`.
Единственный администратор: Telegram ID `8235497168`.

## Что реализовано

- добавление публичных каналов и приватных invite-ссылок через Telegram-бота;
- автоматическое вступление личного аккаунта в источник;
- сбор новых и старых постов по количеству, периоду или дате;
- приоритет самых активных постов по просмотрам, реакциям и пересылкам;
- постоянное пополнение очереди до 12 постов;
- дедупликация по Telegram-посту, media ID, метаданным и SHA-256 файла;
- расписание `08:00, 10:00, 12:00, 14:00, 18:00, 21:00` по Москве;
- правило `14:00 video`, которое можно изменить командой;
- фото, видео, альбомы, аудио и документы;
- видео больше 20 МБ через Telethon, без ограничения Telegram Bot API;
- удаление всех исходных URL, скрытых ссылок, кнопок и `@username`;
- обязательная единственная ссылка
  `[НАШ ТГК](https://t.me/webm4ik)` под каждым сообщением MAX;
- изменение подписи через Telegram без передеплоя;
- подписанные QStash endpoints, атомарные leases и восстановление после сна.

## Безопасность перед запуском

Секреты, коды входа и StringSession нельзя отправлять в чат или коммитить.
Если токен, API hash или активная Telegram-сессия уже раскрывались, сначала
перевыпустите соответствующие данные и завершите старую сессию в настройках
Telegram. Файл `.env` игнорируется Git.

Проверка владельца выполняется только по numeric ID `8235497168`. Username
`@pythonvoin` не даёт права управления и может быть изменён без влияния на
сервис.

## Локальная подготовка

Нужен Python 3.12.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
```

Не передавайте `.env` командам, которые выводят его содержимое. Для генерации
переносимой Telegram StringSession задайте только API ID/hash в окружении:

```bash
TELEGRAM_API_ID=... TELEGRAM_API_HASH=... .venv/bin/python -m app.cli session
```

Telegram попросит номер, одноразовый код и, при наличии, пароль 2FA. Полученную
строку вставьте непосредственно в секрет `TELEGRAM_SESSION_STRING` на Render.
Она равносильна активному входу в аккаунт.

Проверка уже созданной сессии:

```bash
.venv/bin/python -m app.cli verify-session
```

## Neon Postgres Free

1. Создайте проект в Neon и скопируйте pooled connection string.
2. Сохраните её как `DATABASE_URL` на Render. URL формата `postgresql://`
   автоматически переводится в драйвер `asyncpg`; `sslmode=require`
   преобразуется в `ssl=require`.
3. После настройки окружения выполните `python -m app.cli init-db` либо
   передеплойте сервис: схема создаётся безопасно при старте.

Файлы, очередь, источники, расписание и история дублей переживают сон и
перезапуск Render. На локальном диске Render хранится только временная копия
медиа на время одной отправки.

## Новый MAX-канал

1. Добавьте MAX-бота администратором канала `channel_animenaruto` с правом
   публикации.
2. Если бот давно добавлен, удалите и добавьте его снова, чтобы появилось новое
   событие.
3. С локальной машины задайте новый `MAX_BOT_TOKEN` и выполните:

```bash
MAX_BOT_TOKEN=... .venv/bin/python -m app.cli discover-max
```

4. Найдите строку, относящуюся именно к `channel_animenaruto`, и сохраните её
   `MAX_CHAT_ID` на Render. Старый numeric ID удалённого канала использовать
   нельзя.

## Upstash QStash Free

Создайте QStash и скопируйте три значения в Render:

- `QSTASH_TOKEN`;
- `QSTASH_CURRENT_SIGNING_KEY`;
- `QSTASH_NEXT_SIGNING_KEY`.

При старте сервис создаёт одно обслуживание каждые 30 минут и по одному
расписанию на каждое время публикации. Шесть стандартных времён плюс
обслуживание занимают 7 из 10 доступных активных schedules. Поэтому через бота
разрешено максимум 9 времён публикации.

Ручная повторная синхронизация:

```bash
.venv/bin/python -m app.cli sync-schedules
```

## Render Free

1. Подключите этот GitHub-репозиторий как Blueprint по `render.yaml`.
2. Заполните все переменные с `sync: false`.
3. `PUBLIC_URL` задайте равным фактическому HTTPS URL Render, например
   `https://telegram-max-crossposter.onrender.com`.
4. Дождитесь `Deployed` и проверьте `/healthz`.
5. Зарегистрируйте webhook управляющего Telegram-бота:

```bash
.venv/bin/python -m app.cli register-webhook
```

6. Напишите боту `/status`, затем отправьте
   `https://t.me/animeworldmem` или `/add_source ...`.
7. Выполните `/parse 100`; `/queue` должна показать заполненные слоты.

Render Free засыпает после простоя. Это ожидаемо: QStash разбудит web service.
Публикация может задержаться на холодный старт, но durable queue не исчезнет.

## Команды владельца

```text
/start, /help, /status
/add_source <ссылка>       или просто ссылка t.me
/sources
/del_source <номер|ссылка>
/parse [количество]
/parse_period <7d|12h> [количество]
/parse_from <ДД.ММ.ГГГГ> [количество]
/parse_top <7d> [количество]
/build                     псевдоним /parse
/queue [количество]
/refresh
/now <ссылка на Telegram-пост>
/times [08:00,10:00,...]
/slot <ЧЧ:ММ> <any|video|image>
/signature
/signature <текст> | <https://ссылка>
/signature_reset
```

`/now` публикует сразу и не удаляет запланированные строки. Если тот же пост
позже дойдёт до своего времени, он будет пропущен как дубль.

## Подпись и очистка ссылок

По умолчанию к каждому MAX-сообщению добавляется:

```html
<a href="https://t.me/webm4ik">НАШ ТГК</a>
```

Настройка читается непосредственно перед публикацией, поэтому изменение
применяется и к уже заполненной очереди. Исходные видимые URL, hidden links,
кнопки и username удаляются. Обычный текст, жирный, курсив, подчёркивание,
зачёркивание и код сохраняются. Ссылку, нарисованную внутри картинки или видео,
текстовый фильтр удалить не может.

## Ограничения медиа

- изображение: до 50 МБ;
- видео: до 250 МБ;
- аудио: до 256 МБ и 60 минут;
- файл: до 4 ГБ, дополнительно ограничен свободным временным диском Render;
- до 12 фото/видео в одном MAX-сообщении, остальное делится.

Файл скачивается Telethon на временный диск, SHA-256 считается блоками по 1 МБ,
после чего файл передаётся MAX как потоковый multipart и удаляется в `finally`.
